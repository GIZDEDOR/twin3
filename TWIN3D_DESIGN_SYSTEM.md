Срез локального репозитория на **31 октября 2026**. Ветка `codex/project-case-template`, HEAD `8fd33edc5104a6ae3cd1f5f011d8df7d959d3595`. До создания этой спецификации не было staged/unstaged изменений отслеживаемых файлов. Единственный untracked — `tests/koala-intro.test.mjs`: тест видеоинтро, не импортируется интерфейсом. ## 2. Шрифты и типографика

Источник: [globals.css](app/globals.css), [tailwind.config.ts](tailwind.config.ts), [layout](app/layout.tsx). Локальные URL от корня сайта, обычный CSS @font-face, все шесть деклараций — TrueType, normal (прямые), не variable fonts. В приложении нет вызова next/font, генерируемого класса Next или CSS-переменных вида --font-*. Геист из шаблонного README не источник. Body — font-druk antialiased; поверхность кейса сознательно сбрасывает семейство на Standard.

Никаких отдельных начертаний для font-semibold, font-extrabold и т. п. сайт автоматически не загружает: это запрашиваемые CSS-веса; браузер подбирает доступное лицо и может синтезировать насыщенность. В [public/fonts](public/fonts) также лежат два Druk Bold Desktop OTF (400/700), Franklin Gothic Medium Cond.TTF, FRADMCN-700-normal-0.ttf и RG StandardMedium-700-normal-0.ttf. Они не являются src перечисленных @font-face. Не заменять ими кириллический Druk и Book без сравнения.

### Рабочая шкала (mobile → wide)

Ниже px, если не указано иначе; unitless leading умножается на размер шрифта. Для расшифровки стандартных rem-утилит принято 1rem = 16px; фиксировать пользовательский root-size не требуется. Там, где tracking/leading не переопределён, сохраняется каскад, а не выдуманный токен.

## 4. Компоненты, композиция, адаптивность

**Header.** Desktop от md: fixed top-4 (16px), по центру, ширина calc(100% - 48px), максимум 1720, radius 15, padding 14px 21px, z-50. Навигация с gap 20, пункты высотой 36, логотип h-8. Бургер — девять точек 3×3px, gap 2. На mobile ширина calc(100% - 24px), radius 16, padding 8px 16px, вместо ряда ссылок Show Menu, логотип h-5. Скрытие через translateY(-120%), 300ms. В открытом меню на десктопе две видеоколонки по трети и треть с пунктами; на телефоне только панель, шириной во весь экран. Не смешивать стеклянный Header и непрозрачное меню.

**Каталог.** [CaseFilters](slices/CaseFilters/index.tsx): наружные поля px-4; сетка max-width 1200, одна колонка, с sm две, gap-8 (32). Внутри карточки flex column, 1px #767676, radius 20, padding 20px 20px 23px, shadow-lg. Постер h-240px → с md 345px, radius 18, overflow hidden; видео/постер object-cover. Тег прижат вправо вниз: offsets 8 → 20px, padding 3px 8px → 9px 20px; radius 6 → 12. После медиа 20px. Под описанием намеренно большой mb-72px. Нижний ряд mt-auto, justify-between/items-end: кнопки слева с gap 12.8, логотип справа: height 40, width auto, max-width 28%, min-width 0, shrink, contain, opacity .9. Вместо увеличения изображений через intrinsic size ограничивать собственный box логотипа. Кнопка radius 7 → 12, padding 4px 12px → 9.6px 12.82px. Подфильтры на мобильном w-full, с sm w-auto; высота **не** универсальная. Основные категории в мобильной композиции на фоне h-600px; не копировать эту высоту в экран выбора упражнений.

**Главная, карточки разного назначения.** [HeroSlice](slices/HeroSlice/index.tsx): видео cover, тёмный слой, крупный Druk, отдельный Showreel CTA. [Showreel](slices/Showreel/index.tsx) как самостоятельный slice — полноширинное muted loop playsInline видео с controls на чёрном фоне. [CaseGrid](slices/CaseGrid/index.tsx) главной — не каталог: рамка, чёрный внутренний блок с padding 10, radius 18 → 14 при hover; на md сетка 1fr 1fr auto, gap 6, вертикальная техническая подпись ProtoMono 15/15. [CategorySlyder](slices/CategorySlyder/index.tsx): короткие кнопки направлений radius 12, flex-wrap gap 8/12, контейнер до 1000. [StatsGrid](slices/StatsGrid/index.tsx): три колонки, gap 4/16, px-4, max-w-6xl; крупная цифра наверху, короткая подпись внизу. Награды — отдельный широкий модуль с золотым контуром, на мобильном занимает три колонки; не делать все карточки одинаково яркими. [TeamSlice](slices/TeamSlice/index.tsx): горизонтальная галерея Swiper, 160×160 круглые портреты с контуром #626262, короткие Franklin-имена.

**Блог и технологии.** У NewsGridSlice один столбец → md два, gap 32; карточка #1a1a1a с padding 16, border #333 → #555, radius 16; фото высотой 300, radius 12. Это полезные альтернативы сплошной стене одинаковых «плиток».

**Детальная страница и оверлеи.** У [листа кейса](components/projects/project.module.css) fixed inset 0, z-index 130, height 100dvh, overflow-y:auto, overscroll-behavior:contain. Desktop padding 24px clamp(12px,3vw,48px), sheet max-width 1600, radius 20. Контентный gutter clamp(24px,5vw,88px). Верхняя строка sticky top:-24px, min-height 76; close 48×48 круг. На ≤640: снаружи 10px 8px, sheet radius 16, min-height calc(100dvh - 20px), toolbar top:-10px, min-height 68, close 44×44, внутреннее поле 20. Заголовок во всю ширину; далее 1.4fr/1fr, на ≤900 одна колонка. Паспорт 2 → при ≤900 три → при ≤640 две колонки; это намеренно не линейная шкала.

Основное видео занимает обе колонки; дополнительные в сетке 2 → 1. Соотношение 16:9, contain; обёртка clips radius 12, фон видео transparent. Медиа выдвинуто за текстовый gutter на 0.55 его ширины с каждой стороны. История разделена линиями, сетка 1fr/1.55fr с gap 7%, на мобильном — одна колонка. Галерея 1.2fr/1fr, чётные изображения сдвинуты вниз на 72px, на мобильном сдвиг обнулён. «Результат» — микрометка, одна крупная голубая фраза, затем нормальный текст. Related — три колонки → одна; превью 16:10, заголовок Franklin 28/1.2. Отдельная видеомодалка каталога проще: z-120, black/80, backdrop-blur-sm, max-w-3xl, aspect-video, close 36px. Модалка новости — скроллируемый лист max-height 90vh, radius 16. Не переносить одновременно три механизма диалогов в новое приложение: взять визуальный рецепт, сохранить существующий механизм открытия и возврата.

**Footer.** На главной портрет image76.webp и огромная серая строка, а не сетка карточек. Строка Druk 40vw → 18vw, ведущая 1, opacity .2, градиент #C3C3C3 → #999999; контейнер h-32vw → 14vw. В этом срезе портрет на mobile w-96vw, margin-bottom calc(25vw + 24px); desktop absolute, right calc(50% - 11px), размеры по брейкпоинтам 45/40/38/36vw, cap 880px. Соцссылки Franklin с белым контуром 20%, radius 10.61, hover white/10. У [Footer](components/Footer.tsx) на других страницах иная компоновка: mobile #0B0B0B и верхний радиус 20. Обобщать конкретные координаты портрета на изображения спортсменов не нужно.

**Ритм.** У сеток нет единого max-width: header 1720, sheet 1600, каталог 1200, технологии 1213, текст ограничен в ch. Повторяются внешние поля 16–20 на телефоне, интервалы 8–12 внутри управляющей группы, 16–24 внутри карточки, 32 между самостоятельными модулями, 64 и более между главами. Это наблюдение, не набор объявленных --space-N. Стандартные Tailwind breakpoints здесь sm 640, md 768, lg 1024, xl 1280, 2xl 1536; локальные media queries CSS Modules могут включать ровно 640px. [VhSetter](components/VhSetter.tsx) вычисляет --vh как innerHeight × .01 при mount и resize; глобально есть 1vh/1dvh fallback, .full-vh и height.screen=100dvh. Не переносить абсолютные координаты, 100vh и фиксированные ширины 375px как универсальный mobile layout.

**Оговорка о сборке.** Tailwind content в этой ветке сканирует app, components и pages, но не slices. Утилита из slice есть в собранном CSS только если попала туда другим путём; CSS Modules от этого не зависят. В таблицах приведены значения исходной разметки, не обещание, что каждый уникальный utility присутствует в каждом бандле. При переносе сканировать реальные каталоги нового приложения либо явно записать ключевые правила в CSS. Не переносить несуществующие классы как токены. Здесь не проводилось измерение computed styles production.

## 6. Что делает это именно Twin3D

1. **Смена голоса шрифтом.** Узкий крупный кириллический Druk для одного сообщения; Franklin для команды; спокойный Standard для чтения; ProtoMono только для данных. Одинаковый гротеск для всех четырёх ролей разрушает сходство быстрее, чем изменение радиуса.
2. **Графит и серебро занимают площадь.** Голубой появляется там, где есть выбор, действие или главный результат. Ни основной фон, ни каждый заголовок не окрашены в синий.
3. **Медиа и типографика задают композицию.** Большой кадр, контрастная короткая строка, число с небольшой подписью, затем воздух или тонкий разделитель. Длинная статья не собрана из одинаковых плашек.
4. **Слои имеют назначение.** Прозрачность у плавающей навигации и ярлыка над изображением, плотная читаемая плоскость у основного текста. Движение подчёркивает вход и направление; характер не зависит от конкретной коалы, логотипов или клиентских кейсов.

## 7. Как перенести дизайн Twin3D в Telegram Mini App

**Всё в этом разделе — рекомендации для «ШАРЬ», не обнаруженные в Twin3D экраны, токены или Telegram-интеграция.** Основная контрольная ширина 390 CSS px. Переносится визуальная иерархия, а не портфолио студии и не его архитектура.

| Экран «ШАРЬ» | Образец Twin3D | Практическое применение |
|---|---|---|
| Курсы | CaseFilters + CaseGrid | Одна колонка, поле 16, gap 16–24; обложка стола/удара, на ней уровень, Standard 20/1.2 для названия, описание 16/1.4. Одна заметная команда «Продолжить». Статус завершения остаётся текстовым, а не только цветовым |
| Урок | ProjectDetail | Номер и длительность в ProtoMono, короткий Druk около 42/1.04, видео 16:9, затем объяснение Standard 19/1.5. Для длинного названия разрешить перенос. Разделить задачу, технику удара и критерий успеха тонкими линиями. Не убирать имеющиеся перемотку, прогресс и действия |
| Тренировка | CTA кейса + StatsGrid | Оставить порядок шагов, таймер, паузу, повторы и сохранение; текущая величина крупным Druk, единица и счётчик подходов — отдельные подписи. Для старта/продолжения явное активное состояние; исключить непрерывную анимацию вокруг таймера |
| Статистика | Результат кейса + числовые блоки | Одна главная цифра голубая; её смысл поясняется обычным шрифтом. Остальная статистика нейтральна. Длинные подписи и периоды не втискивать в три одинаковых столбца; на 390 при необходимости два/один |
| Профиль | Паспорт + toolbar | Метка/значение, ясные группы полей, видимый фокус, достаточно контраста для редактирования. Не заменять привычные формы крупными рекламными заголовками |
| Общая навигация | Header, не триптих fullscreen-меню | Сохранить существующие маршруты и возврат, выделять активный раздел спокойной заливкой; мобильные действия не зависят от hover. Не вводить второе меню параллельно существующему |

**Liquid Glass — прогрессивное дополнение.** В веб-приложении это визуальная интерпретация, не автоматическое подключение нативного материала Apple. Начать с двух поверхностей: плавающая панель навигации и toolbar/панель действий над видео. В качестве базы взять из Twin3D чёрный с альфой .6 и белый контур .1; тонкий направленный блик — дополнение «ШАРЬ». Под стеклом оставить контент видимым, над ним — чёткие иконки и текст. На читаемом листе урока оставить плотный #1A1A1A. Если размытие недоступно/тормозит, повышать непрозрачность поверхности. Не делать большой blur на нескольких перекрывающихся полноэкранных слоях, особенно поверх играющего видео.

**Порядок внедрения и приёмка.**

1. В другом репозитории установить, какие компоненты реально рендерят пять экранов. Зафиксировать исходное поведение: запуск урока, возврат к курсу, сохранение результата, таймер, профиль. Менять слой представления; не заменять модели, навигацию, Telegram SDK и хранение данных.
2. Подключить нужные файлы шрифтов при наличии прав на использование в новом приложении. Для точного вида в первую очередь нужны четыре: DrukCyr, FRAMDCN(cond), RG-StandardBook, ProtoMono-Light. Для буквального воспроизведения средней узкой надписи — ещё FRADMCN-med. Сохранить регистр имён, проверить в браузере кириллицу, «Ё», знак процента и цифры при реально загруженных шрифтах. Один Markdown шрифтов не содержит.
3. Сделать вертикальный срез «Курсы → Урок → Назад». На 390px проверить длинное русское название, несколько строк текста, запомненный скролл, постер и доступность кнопок. Затем распространить роли на тренировку, статистику и профиль.
4. Использовать данные о доступной высоте и безопасных отступах, которые уже получает приложение от Telegram; при их отсутствии предусмотреть CSS safe-area и viewport fallback. Не складывать автоматически два inset для одной и той же системной панели. Проверить развернутый/свернутый WebView, системную кнопку назад, клавиатуру над полями профиля и нижнюю панель на iOS **и** Android. Соблюдать существующую тему хоста там, где это требуется оболочке.
5. На сенсорном экране ввести pressed/selected/focus вместо hover-only. Держать touch-target порядка 44px и больше, как мобильный close кейса. Не переносить тёмный #444 для единственной важной команды на тёмном фоне. С reduced motion оставить управление и статические состояния; при открытии модалки вернуть фокус и скролл после закрытия.
6. Перед сдачей показать реальные скрины пяти экранов на 390px и хотя бы одного более узкого; проверить Telegram на физических устройствах, динамическую высоту, увеличенный текст, длинные числа, отсутствие бокового скролла. Сравнивать в первую очередь форму кириллицы, масштаб заголовка относительно текста, насыщенность графита, один голубой акцент и читаемость поверх видео. Не считать скрин из desktop viewport подтверждением поведения iOS WebView.
