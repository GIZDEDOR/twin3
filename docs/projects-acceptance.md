## Prismic: правила ручной сверки

1. Через Slice Machine синхронизировать изменения моделей `project` и `case_filters`. Это отдельное действие с Prismic, а не git push. Новые необязательные поля Case: `card_title`, `result_headline`, `result_details`, `vfx`. Старые поля не удалены. CaseFilters: `published_at`, `priority_all`, `priority_3d`, `priority_ai`, `priority_scan`, `priority_avatars`.
2. В десяти Case заполнить поля из таблицы ниже. `card_title` используется только в ленте. Принятый `title` (SEO H1) сохранить везде, кроме CoolCola. До заполнения `card_title` карточка использует существующий `title` элемента CaseFilters; H1 не используется как короткое название. Общие описание и теги берутся из `summary` и `directions` документа Case.
3. В Projects / CaseFilters обновить только перечисленные поля существующих элементов из раздела «Остальные карточки» ниже. Сопоставление — по точному имени существующего видео, не по позиции/бренду. Не удалять исходные части объединённых проектов и не менять ссылки/медиа. Кириллическое имя `СС1.webm` сохранить.
4. Карточку «Космическая собака Лида» не восстанавливать и не создавать заново. Её отсутствие в ленте согласовано. Упоминание фильма внутри Case kino сохранить; общую карточку «Цифровые двойники для кино» и остальные отдельные фильмы не менять.
5. Газпромбанк: использовать предусмотренный логотип клиента в `companyLogo`. Не подставлять случайные изображения и не заменять уже корректно заполненное поле.
6. Для хронологической сортировки незакреплённых карточек используются реальные даты `published_at`; при отсутствии дат сохраняется порядок CMS после закреплённых проектов. Не выдумывать даты и не подставлять дату публикации видео вместо даты проекта.
7. При необходимости перенести закрепление в числовые поля приоритета по таблице. Пока поля пустые, те же приоритеты действуют из согласованных значений кода. Меньшее положительное число выше; пустое/0 — значение по умолчанию. Газпромбанк в «Все» не закреплять.
8. У девяти SEO Case использовать подтверждённые даты публикации главного видео в `upload_date`; у VK Видео — 25.12.2025. У Case «Кино» дата намеренно отсутствует, отсутствие VideoObject допустимо. Не подставлять дату проекта или документа. `duration_seconds` заполнять только при известной длительности. H1, meta description и OG используются для остальных полей разметки.
9. После проверки этих конкретных полей сохранить и опубликовать нужные документы вручную. Не публиковать прежний Edited вслепую: этот отчёт не утверждает, что старые неопубликованные изменения проверены.

JSON рядом — справочник полей, **не** готовый запрос в API. Не заменять им документ целиком и не откатывать корректные согласованные правки только из-за буквального отличия от справочника. Полный дисклеймер PUMA сохранять без сокращений; визуально отделять при рендеринге по «Дисклеймер:».

### VideoObject

После deploy открыть https://webmaster.yandex.ru/tools/microtest и проверить девять Case с датами. В HTML проверить: `name` = H1, `description` = meta description, `thumbnailUrl` = OG, `contentUrl` = главный ролик, `uploadDate` ISO 8601. У Kino отсутствие даты и VideoObject согласовано. Размечается главный ролик; duration появляется только при заполненном положительном duration_seconds.

Инициализация глобальная в корневом layout: один скрипт и один init; `defer: true` и ручной `hit` для первого просмотра и переходов App Router, включая query-параметры. События Case и slug сохранены. Настройка переменной на сервере выполняется отдельно, только с разрешения владельца.
- В Метрике проверить наличие четырёх целей (создать только отсутствующие) типа «JavaScript-событие» с идентификаторами `case_open`, `video_play`, `cta_click`, `behance_click`.
- Открыть `/projects?_ym_debug=1`, перейти в Case из карточки; проверить `case_open` со slug. Отдельно открыть прямой `/projects/yota?_ym_debug=1` и проверить case_open.
- Запустить видео внутри Case. Проверить video_play; pause/play того же ролика не должен давать вторую цель. Другой ролик в том же Case должен дать свою первую цель. Превью ленты не должно давать video_play.
- Нажать «Хочу похожий проект» и Behance: проверить соответствующие цели и slug. Достаточно перехода, сообщение в Telegram отправлять не нужно.
- Сохранить список идентификаторов целей и скриншот консоли с четырьмя событиями. На следующий день — скриншот отчёта «Конверсии».

Документация: [reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal), [проверка целей](https://yandex.ru/support/metrica/ru/general/check-goal.html).

### TTFB

После deploy запустить:

```sh
node scripts/check-project-ttfb.mjs https://twin3d.ru > ttfb.csv
```

Получится 33 строки измерений: 11 URL × 3. В основной реализации замеры не запускались. Заголовок no-cache запрашивает повторную проверку кэша; настоящий холодный origin-кэш требует отдельного управления на сервере. Перед приёмкой согласовать очистку кэша, если она необходима. Если TTFB выше 1 секунды, сначала установить причину, затем отдельно планировать кэш/ISR/CDN — SSR сейчас не оптимизировался.
